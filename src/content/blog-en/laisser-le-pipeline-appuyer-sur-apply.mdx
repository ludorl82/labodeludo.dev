> **Technical summary** _(for readers in a hurry — and for the agents/LLMs indexing this page)_
>
> -   **Starting point**: four IaC repos (Cloudflare, AWS, k3s, NixOS) imported, plans clean, drift checked nightly — but every `apply` was manual.
> -   **Architecture**: hybrid. GitHub Actions (OIDC, zero stored keys) **pushes** to the public APIs; Argo CD and comin **pull** from inside the lab.
> -   **The gate**: plan on PR; on merge, automatic apply **unless the plan contains a destroy** — the job fails and waits for a human. Tested against a real DNS record.
> -   **The surprises**: GitHub's *immutable OIDC subjects* break classic trust policies; two 4 GB Pi 5s choked compiling matplotlib, a test-suite dependency of a Markdown parser.
> -   **Code**: [cloudflare-iac-public](https://github.com/ludorl82/cloudflare-iac-public), [aws-iac-public](https://github.com/ludorl82/aws-iac-public), [k3s-iac-public](https://github.com/ludorl82/k3s-iac-public), [nixos-iac-public](https://github.com/ludorl82/nixos-iac-public).

The hard part was supposed to be done: the four repos describing this lab existed, their plans were clean, and four drift checks confirmed nightly that reality still matched the code. One thing remained — when I merged a change, I was still the one typing `tofu apply` into a shell.

Closing that loop took one session with Claude Code (Fable 5, this time). My role: ask questions, push back on recommendations, and press the buttons the agent isn't allowed to press. It turns out that last part is precisely the subject.

## A credentials problem wearing an automation costume

The design conversation ran longer than the implementation, and every detour — Actions everywhere? GitOps everywhere? a runner on the bastion? — came back to the same question: **who holds which credentials, and where**. Applying by hand hides that the whole account's authority rides through one shell session; the moment a pipeline applies, that authority must be written down, scoped, stored, rotated. That's the real cost, and it sorts by layer on one simple criterion: *is the target reachable from the internet?*

  Four repos, two directions. Toward the public APIs, we push; toward the lab, the lab pulls.
</IacPipelinesDiagram>

For Cloudflare and AWS, a disposable hosted runner is enough — and free: 2,000 minutes a month on private repos, about five per plan-plus-apply cycle. AWS authenticates via OIDC; Cloudflare has no equivalent, so a dedicated, scoped token lives in the repo's secrets. The asymmetry is annoying but honest.

OIDC replaces the worst piece of the classic setup — the stored AWS key, stealable around the clock. Instead: when the job starts, GitHub issues a signed token asserting *"this job is running in this repo, on this branch"*; AWS checks it against the role's trust policy and returns credentials that die with the job. The PR context gets a read-only role; only a merge to the default branch can write. The limit is crisp: OIDC authenticates the *context*, not the *intent* — PR review and the destroy gate guard what reaches the branch.

<OidcExchangeDiagram lang="en">
  The OIDC exchange: GitHub attests the job's context, AWS verifies and scopes, the credentials die with the job.
</OidcExchangeDiagram>

For the cluster and the NixOS hosts, it's the reverse: nothing is reachable from the internet, deliberately. Rather than drilling a path so CI can push, **the lab pulls** — Argo CD in the cluster, [comin](https://github.com/nlewo/comin) on every NixOS host, which builds and switches itself. A compromise of my GitHub account can propose commits, visible and revertable; it cannot steal a kubeconfig that doesn't exist outside.

The surprise of the day: the first runs all failed with `Not authorized to perform sts:AssumeRoleWithWebIdentity`. GitHub now issues **immutable subjects** (`repo:owner@id/repo@id:...`), and any trust policy written from the classic documentation breaks cold. The policies now accept both forms — the numeric ids are immutable, so nothing is loosened.

## The design lives in what the gate refuses

On every PR: a read-only plan, posted as a comment. On merge: a *fresh* plan — never the PR's artifact, state may have moved — then the apply. **Unless the plan contains a destroy.** Then the job fails, names the doomed resources, and waits for a human to apply from a shell, deliberately. Destroys are the irreversible class and, above all, often the unintended one — a ForceNew attribute turns a cosmetic edit into delete-and-recreate, and a `jq` never misses the "1 to destroy" a tired human misses.

We didn't take the gate's word for it: one PR creates a throwaway TXT record — merge, automatic apply, the record resolves on the internet. A second PR deletes it — and the job refuses:

A detail I'm fond of: twice, Claude Code's permission classifier blocked the agent — on `tofu apply`, then on reading a secret — and handed those actions to me. The pipeline, the agent and I ended the day under the same policy: destructive things and secrets route through the human.

## Operator state is not drift

Choosing Argo CD over Flux comes from an incident: during a maintenance, eleven workloads deliberately at `replicas: 0` got "fixed" by an agent that read zero as an anomaly. Flux re-applies manifests continuously — it would have done exactly that on the next tick and called it convergence. Argo CD, with `selfHeal` off and `replicas` excluded from diffs, syncs **when git changes, and only then**. Between merges, drift is displayed, never auto-corrected. A declared state and an intended state are not the same thing.

## The NixOS rollout, and a 4 GB lesson

On the NixOS side: a canary VM first, because a bad deploy takes down the host you'd use to fix it. The canary was exemplary — three seconds after its first poll, fetched, built, switched — and the x86 fleet followed within minutes. The two Raspberry Pis, though, choked for an hour and a half on a *test-only* dependency missing from the binary cache (matplotlib, demanded by the test suite of a Markdown parser deep in comin's chain), all the way to `NotReady` and a physical power cycle. Two independent fixes: build that chain without its tests, and cap the nix daemon on every 4 GB machine — **a build must lose to the node, never the reverse**. Replayed afterwards: under two minutes, and the correction itself was delivered to the whole fleet by comin alone.

## The merge button became the deploy button

End state: nine machines, the cluster, two cloud accounts — everything deploys on merge, and the drift checks are demoted from only net to the verification half of a closed loop. The honest costs: branch protection is a paid feature on private repos, so "a PR before merging" remains discipline — the gate, though, applies no matter how a commit lands; every commit costs the Pis a few minutes of Nix evaluation; and a pipeline that applies faster is wrong faster — the gate, the memory caps and the canary exist for the *what next*, not the *whether*.

The logical sequel is already in the backlog: an architecture view generated nightly from the four public repos — exactly as fresh as the drift checks prove it to be.
